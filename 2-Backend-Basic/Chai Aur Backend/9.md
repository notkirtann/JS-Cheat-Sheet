# User & Video Backend Architecture (MongoDB + Mongoose + JWT)

This document explains the complete backend structure for **User and Video models**, authentication flow, schema design decisions, and security practices using **MongoDB, Mongoose, Bcrypt, and JWT**.

---

# 1. Overview

The system consists of:

* **User Model**
* **Video Model**
* Authentication using **JWT**
* Password security using **Bcrypt**
* Relationships:

  * User → Watch History
  * Video → Owner (Uploader)

---

# 2. User Model

## 2.1 Fields

| Field        | Type       | Description            |
| ------------ | ---------- | ---------------------- |
| username     | String     | Unique username        |
| email        | String     | User email (unique)    |
| fullName     | String     | Full name              |
| password     | String     | Hashed password        |
| watchHistory | ObjectId[] | List of watched videos |
| refreshToken | String     | Stored refresh token   |

## 2.2 Schema Example

```js
import mongoose from "mongoose";
import bcrypt from "bcrypt";
import jwt from "jsonwebtoken";

const userSchema = new mongoose.Schema(
{
    username: {
        type: String,
        required: true,
        unique: true,
        lowercase: true,
        trim: true,
        index: true
    },
    email: {
        type: String,
        required: true,
        unique: true,
        lowercase: true,
        trim: true
    },
    fullName: {
        type: String,
        required: true,
        trim: true
    },
    password: {
        type: String,
        required: true
    },
    watchHistory: [
        {
            type: mongoose.Schema.Types.ObjectId,
            ref: "Video"
        }
    ],
    refreshToken: {
        type: String
    }
},
{ timestamps: true }
);
```

# 3. Video Model

## 3.1 Fields

| Field       | Type     | Description         |
| ----------- | -------- | ------------------- |
| videoFile   | String   | Video file URL/path |
| thumbnail   | String   | Thumbnail image     |

| description | String   | Video description   |
| duration    | Number   | Duration in seconds |

# 5. Password Security (Bcrypt)

## 5.1 Why Hash Passwords?

Never store passwords in plain text.

Hashing ensures:

* Data safety if database leaks
* One-way encryption

---

## 5.2 Pre-Save Hook

```js
userSchema.pre("save", async function(next) {
    if (!this.isModified("password")) return next();

    this.password = await bcrypt.hash(this.password, 10);
    next();
});
```

---

## 5.3 Password Comparison Method

```js
userSchema.methods.isPasswordCorrect = async function(password) {
    return await bcrypt.compare(password, this.password);
};
```

# 6. JWT Authentication

## 6.1 What is JWT?

A token used for secure authentication.

Structure:

* Header
* Payload
* Signature

---

## 6.2 Access Token

Short-lived token for API access.

```js
userSchema.methods.generateAccessToken = function() {
    return jwt.sign(
        {
            _id: this._id,
            email: this.email,
            username: this.username
        },
        process.env.ACCESS_TOKEN_SECRET,
        { expiresIn: "15m" }
    );
};
```

---

## 6.3 Refresh Token

Long-lived token used to generate new access tokens.

```js
userSchema.methods.generateRefreshToken = function() {
    return jwt.sign(
        { _id: this._id },
        process.env.REFRESH_TOKEN_SECRET,
        { expiresIn: "7d" }
    );
};
```

# 7. Authentication Flow

### Login

1. User enters email & password
2. Find user in DB
3. Compare password using bcrypt
4. Generate:

   * Access Token
   * Refresh Token
5. Store refreshToken in DB
6. Send tokens to client

---

### Token Refresh

1. Client sends refresh token
2. Verify token
3. Generate new access token

# 9. Environment Variables (Security)

Sensitive data should not be hardcoded.

Example `.env`

```
ACCESS_TOKEN_SECRET=your_access_secret
REFRESH_TOKEN_SECRET=your_refresh_secret
MONGO_URI=your_database_url
```

Why?

* Prevent leaks
* Safe for production
* Easy configuration
