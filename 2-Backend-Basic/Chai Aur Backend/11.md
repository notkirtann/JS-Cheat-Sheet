## **Video Notes: Controller and Router Setup (Part 2)**

* **Topic:** Backend Architecture (Controllers, Routes, and Error Handling)
* **Tech Stack:** Node.js, Express, JavaScript (CommonJS/ES6)
* **Current Goal:** Setting up the registration flow and API structure.

---

### **1. Controller Setup**

* **File:** `user.controller.js`
* **Purpose:** To house the actual logic (the "brains") of user-related requests.
* **Action:** Created a dedicated file to keep the code modular and separate from route definitions.

### **2. The `asyncHandler` Wrapper**

* **Implementation:** A higher-order function used to wrap asynchronous controller functions.
* **Why use it?** * Streamlines error handling.
* Eliminates the need for repetitive `try-catch` blocks in every controller.


* **Debugging Tip:** A common pitfall is forgetting a `return` statement or proper `next()` call within the wrapper, which can cause the app to hang or crash.

### **3. Router Configuration**

* **File:** `user.routes.js`
* **Logic:**
* Import `Router` from Express.
* Import the controller functions (e.g., `registerUser`).
* Define the method: `router.route("/register").post(registerUser)`.



### **4. App Integration & API Versioning**

* **File:** `app.js`
* **Prefixing:** Using `app.use("/api/v1/users", userRouter)`.
* **Best Practice:** Always use **API Versioning** (like `/v1/`). This ensures that if you make breaking changes in the future (to `/v2/`), existing users/mobile apps using the old version won't break.

---

### **5. Testing & Debugging (Postman)**

* **Endpoint:** `POST http://localhost:8000/api/v1/users/register`
* **Common Errors:**
* Sending a `GET` request to a route defined as `POST`.
* Incorrect URL prefixing.


* **Response Handling:** Always send a structured JSON response with appropriate HTTP status codes (e.g., `200 OK` for success) so the frontend can handle the data correctly.
